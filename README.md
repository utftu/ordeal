# ordeal

Запуск эвалов для сервисов на ИИ. Кейс — обычная асинхронная функция: зовёт ваш сервис и возвращает балл от 0 до 100. ordeal запускает кейсы в изолированных воркерах, сравнивает балл с порогом, печатает результат и пишет историю прогонов.

Нужен [Bun](https://bun.sh).

## Эвал

```ts
// support.eval.ts
import { createEval } from "ordeal";

export const returnDecision = createEval("return-decision", (ctx) => {
  ctx.createCase({ name: "брак с фото в срок", minScore: 80 }, async (signal) => {
    const answer = await decideReturn({ photo: true, days: 3 }, signal);

    return { score: answer.verdict === "refund" ? 100 : 0, output: answer };
  });
});
```

- **Файлы** — `*.eval.ts`, `*.eval.tsx`, `*.eval.js`. Эвал нужно экспортировать, имя экспорта значения не имеет. Файл без экспортированного эвала — ошибка, а не тихий пропуск.
- **Имя эвала** уникально в пределах запуска.
- **`ctx.createCase(props, run)`**:
  - `name` — ключ истории, уникален внутри эвала. Переименовали кейс — у него новая пустая история.
  - `minScore` — порог от 0 до 100, обязателен. Кейс, который нужно только измерять, пишет `minScore: 0`.
  - `timeout` — миллисекунды на попытку, по умолчанию 60 000.
- **`run(signal)`** возвращает число или `{ score, output }`. `output` — ответ сервиса как есть: он попадает в вывод и в `latest.json`. Передайте `signal` в свой `fetch`, чтобы кейс успел прибраться при таймауте.
- Кейсы — обычный код: их можно строить циклом по датасету, проверки переиспользовать как функции.

### only и skip

```ts
export const support = createEval("support", { only: true }, (ctx) => {
  ctx.createCase({ name: "брак без фото", minScore: 60, skip: true }, async () => 90);
});
```

- **У эвала** — необязательный второй аргумент: `createEval(name, { only, skip }, fill)`. **У кейса** — поля в props: `{ name, minScore, skip: true }`. `only` и `skip` сразу — ошибка.
- **Флаг эвала решает за все его кейсы**, флаги кейсов внутри не учитываются: в эвале с `only` запускаются все кейсы, даже со `skip`; в эвале со `skip` — ни один.
- **`only` действует на весь запуск:** если хоть что-то в любом файле помечено `only`, запускается только отобранное.
- Пропущенные и неотобранные кейсы не запускаются, печатаются как `case=… skip`, считаются в `skipped=` и на код возврата не влияют. Если в запуске был `only`, общая строка итога показывает `only=N` — не забудьте убрать его перед коммитом.

## Запуск

```sh
ordeal                    # все эвалы от текущей папки вглубь
ordeal evals/support      # только из этих путей
ordeal -t 5 -r 2 -c 8
```

Из репозитория команду можно запустить как `bun src/cli/cli.ts`.

| Флаг | По умолчанию | Что делает |
|---|---|---|
| `--concurrency`, `-c` | число ядер, от 1 до 20 | сколько воркеров |
| `--trials`, `-t` | 1 | сколько раз запускать каждый кейс |
| `--retries`, `-r` | 0 | сколько повторов, если trial бросил исключение |
| `--timeout` | — | мс на попытку, перебивает `timeout` кейсов |

- **`--trials` — измерение.** Кейс запускается N раз, и каждый trial сравнивается с порогом отдельно. Кейс прошёл, только если прошли все trials. Баллы не усредняются.
- **`--retries` — ремонт.** Trial, который бросил исключение (429, таймаут, обрыв), отправляется заново. Балл ниже порога повтора не вызывает.
- Складываются вложенно: `-t 5 -r 2` — пять trials, каждый до трёх попыток.

## Вывод

Во время прогона — строка `start`, когда trial попал в воркер (и на каждый повтор, с `retries=`), и строка на каждый готовый trial:

```text
start eval=return-decision case="брак с фото в срок" trial=1
start eval=failures case="ниже порога" trial=1
fail  eval=failures case="ниже порога" trial=1 score=61 minScore=80 time=2ms output={"note":"ответ неполный"}
ok    eval=return-decision case="брак с фото в срок" trial=1 score=100 time=312ms output={"verdict":"refund"}
start eval=failures case=зависает trial=1
fail  eval=failures case=зависает trial=1 time=2.0s error="TimeoutError: кейс не уложился в 1000мс и был убит"
```

В конце — итог деревом в порядке объявления и общая строка. В терминале `eval=`, `case=` и `trial=` в начале строк итога оранжевые:

```text
eval=failures total=3 passed=1 failed=2
  case="ниже порога" fail
    trial=1 fail score=61 minScore=80 time=2ms output={"note":"ответ неполный"}
  case="падает через раз" ok
    trial=1 ok score=90 time=3ms retries=1
  case=зависает fail
    trial=1 fail time=2.0s error="TimeoutError: кейс не уложился в 1000мс и был убит"
total=3 passed=1 failed=2 time=2.1s
```

`time=` — сколько trial выполнялся в воркере, по всем попыткам вместе, без ожидания свободного воркера. `minScore=` печатается только у trial ниже порога, `retries=` — только если были повторы. `output` обрезается до 200 символов, полный лежит в `latest.json`.

В терминале `ok` зелёный, `fail` красный, имена полей синие. При выводе в файл или пайп, а также с переменной `NO_COLOR` цвета нет.

Код возврата:

- `0` — все кейсы прошли;
- `1` — хоть один кейс не прошёл;
- `2` — запуск сломан: путь не найден, эвалов нет, файл без эвалов, два эвала с одним именем.

## История

В текущей папке появляется `.ordeal/`. Добавьте её в `.gitignore` сами, ordeal его не трогает.

- `.ordeal/history.jsonl` — строка на каждый запуск, без `output`. Когда строк становится больше 200, остаются последние 100.
- `.ordeal/latest.json` — три последних запуска целиком, с `output`, новый сверху.
- `.ordeal/last.json` — только последний запуск, одним объектом, с `output`.

```json
{
  "version": 1,
  "startedAt": "2026-09-12T13:40:11.204Z",
  "ms": 48210,
  "options": { "trials": 3, "retries": 2, "timeout": 60000 },
  "evals": [
    {
      "name": "return-decision",
      "total": 1,
      "passed": 1,
      "cases": [
        {
          "name": "брак с фото в срок",
          "minScore": 80,
          "passed": true,
          "trials": [
            { "score": 94, "ms": 1820, "retries": 0, "output": { "verdict": "refund" } }
          ]
        }

```

## Что важно знать

- **Изоляция.** Кейс выполняется в воркере. Когда время вышло, кейс получает abort через `signal`; если через секунду воркер не ответил, его убивают и заменяют новым. Упавший или зависший кейс не роняет остальные.
- **Состояние модуля.** Код верхнего уровня файла эвала выполняется в каждом воркере и заново после каждой замены воркера. Не рассчитывайте на переменные модуля между кейсами.
- **Одновременность.** Кейсы всех эвалов и все trials одного кейса идут одновременно, в пределах `--concurrency`. Если сервис хранит состояние (создаёт заявку, пишет в одну тестовую учётку), одновременные trials могут мешать друг другу.
- **Порядок.** Строки во время прогона идут по мере готовности, вперемешку. Итог и запись — в порядке объявления.

## Сборка

```sh
bun run build          # dist/: JS и .d.ts
bun run build:js       # только JS
bun run build:types    # только .d.ts
```

Пакет отдаёт `dist/`: `import { createEval } from "ordeal"` и команда `ordeal` работают после сборки.

## Пример

В `examples/` лежат два эвала для ручной проверки: имитация сервиса, который иногда ошибается, и набор неудач — балл ниже порога, падение, которое чинят retries, зависание, которое убивает таймаут. Примеры импортируют `ordeal` по имени пакета, поэтому сначала нужна сборка.

```sh
bun run build
bun dist/cli/cli.js examples -t 3 -r 1
```
